# UI code

Two entry points: the popover (`ui/index.html`, `ui/src/*.ts`, plain TS and CSS) and the editor window
(`ui/editor.html`, `ui/src/editor/`: Preact + Tailwind 4 via `@tailwindcss/vite`, tokens in `editor.css` `@theme`).

## Rules
- TypeScript `strict: true`; no `any`. ESLint, Prettier and `tsc` are gates in `just lint` / `fmt-check`.
- Popover: no framework, plain TS modules and DOM APIs. Editor: Preact (`.tsx`, automatic JSX runtime) is the only framework; no other runtime dependency beyond `@tauri-apps/api` and `preact`. Pin exact versions of preact/tailwind. Plain CSS with custom properties (tokens, same as Deeboo MIDI Sync) in `ui/src/styles.css`; no hard-coded colours or radii outside the token block.
- All text is English. "Smart Life" appears only in the connection flows; never name other third-party software.
- Icon-only buttons need an `aria-label`.
- The UI only talks to Rust through `ui/src/api.ts` (editor: `ui/src/editor/api.ts`); views never import `@tauri-apps/api` directly.
- Webview loads only bundled files: strict CSP, no inline scripts or styles, no remote origins. The QR is rendered locally.
- Never show a secret. The key is shown masked; nothing secret enters the DOM, console or state objects.
- The popover may call only `select_set`, `set_live_set`, `select_palette` (all return the new `Selection`: set name, `paletteAuto`, palette name, its three colours; the palette cycle is Auto, p1 .. pn, Auto over the live set) and `open_editor` besides the status/settings commands; `status.selection` carries the same for rendering.
- Status events arrive only while the popover is visible (max 30 Hz). Write to the DOM only when a value changed (never rewrite text under the pointer; WebKit drops the click).
- The editor window is created on open and destroyed on close. Its simulation animates with `requestAnimationFrame` only while visible; no timers or polling.
- Editor components are tested by mounting with `preact` `render` inside `act` from `preact/test-utils`, with `./api` mocked (`await act(async () => { render(<App/>, root); await new Promise(r => setTimeout(r)) })` lets effects settle). The editor opens through the Rust `open_editor` command, has its own capability file (`src-tauri/capabilities/editor.json`) listing exactly its commands, and its window is never pre-declared in `tauri.conf.json`.
- Editor shell (`ui/src/editor/shell/`, `state/`): `useLibrary()` is the one library store (edit/undo/redo, 400 ms debounced `saveLibrary` (flushed on `beforeunload` and unmount), `coalesce` key = one undo step per gesture); saves always carry the live `activeSet`/`activePalette`, never a history snapshot's. New entries use a temporary client id (counter from 1_000_000); when a save adopts Rust's ids, `diffIds` pairs sent vs saved by index, rewrites every undo/redo state (`remapStates`) and notifies `store.onRemap`, so each tab maps its selected id there (never keep a raw id in tab state without subscribing). Test with `state/renumber-mock.ts` (a `saveLibrary` that renumbers like Rust), not an identity mock. Hover help: every interactive element (button, input, select, slider, toggle, drag handle, list item, SVG piece) carries `{...help(H.key)}` (`data-help`); all texts, one English sentence each, live in `ui/src/editor/help-texts.ts` (edit them there). `HelpProvider` renders the one app-styled tooltip (`role="tooltip"`, sets `aria-describedby` on the target) on mouseover and keyboard focus while the "?" toggle is on, fixed-position and clamped to the window; never the native `title`. `help-coverage.test.tsx` walks all six tabs (and the connection steps) with the mock api and fails on any control without help, so a new control needs a text. Dev only: `?mock&tip=<css selector>` opens that control's tooltip for screenshots. icons are bundled SVGs from `ui/src/icons` (`<Icon name>`), never emoji. `open_editor(section)` (all six tabs) reaches the UI as `?section=` on create, or the `editor-section` event when already open. The editor receives `status` events while open.
- Sequences tab (`SequencesTab`): selection lives in the tab; it hands the top bar `onActions` (Duplicate/Delete for the selection, empty for generated entries). The simulation follows the status beat when the clock plays, else 120 BPM; no BPM control. The clock only gives the phrase position, so the simulation free-runs and each sync moves it to the nearest point with that phase (a 16-bar sequence shows all its bars). Length: `ClipBar` handle (drag or arrows) plus ÷2 / ×2 buttons (`halveBars` keeps the first half, `doubleBars` repeats; 1 to 16 bars, disabled at the limits, undoable); `ArrangementGrid` leaves one empty bar of room after the clip (up to 16) so the handle can lengthen it.
- Sets tab (`sets/SetsTab.tsx`, `Track.tsx`, `PaletteRow.tsx`, `dnd.ts`): Session view with native HTML5 drag and drop (the editor window keeps Tauri's native drop handler off, `editor_window.rs`, or WKWebView never fires `drop`); internal drags set only `DRAG_TYPE` (`editor/drag.ts`, never `text/plain`, so no input swallows the text) and `App` installs `installDropGuard()`, which cancels every dragover/drop no drop zone took (a dropped file or link must never load); `dnd.ts` `canDrop(item, target)` is the single drop rule (a sequence or clip only drops on its own moment's track, palettes only on the palette row) and `moveRef` reorders. All edits go through `useLibrary().edit`; "Play live" calls `api.setLiveSet(id)` then `store.syncLive()` (never `saveLibrary`; `store.liveSet` is the live set). Hold-to-preview on a clip calls `api.previewSequence(on, palette, ref, moment)` (Rust `preview_sequence`, validated like `preview_palette`) and stops on pointerup, leave, blur and unmount. A track keeps at least one sequence and a set at least one palette. Double-clicking a clip opens it in Sequences (`SequencesTab` `initial`). Layout: the tab fills the viewport; the browser column and the tracks area scroll on their own and the palette row is pinned at the bottom; each track's Order/Change every row never wraps (the "Order" word hides under 20rem via a container query). `status.clip` (`{moment, index, elapsed, total}`, from Rust `EngineStatus.clip` / `ClipDto`, pushed with the normal status events) makes the playing clip glow teal with a progress bar, only while the open set is the live one.
- Palettes tab (`PalettesTab`): all edits go through `useLibrary().edit` (wheel, slider and hex drags use `coalesce`). `Show on strip` calls `api.previewPalette(on, palette, sequenceId)` (Rust `preview_palette` validates the palette and that the sequence is in the library and fits the strip; the engine plays it over the show, on the beat when a clock runs, at 120 BPM otherwise); the UI switches it off on tab leave, window blur and `beforeunload`, and Rust switches it off when the editor closes. TopBar `deleteGuard()` lets a tab answer before the confirmation (true = handled).
- Strip tab (`strip/StripTab.tsx`, `SegmentsCard.tsx`, `ShapeCanvas.tsx`, `presets.ts`, `shape.ts`, `Guide.tsx`): shape edits go through `useLibrary().edit` (one undo step per gesture or key press; the canvas keeps a local draft while dragging). Pieces are one-cell-wide bars at any 15-degree angle (Rust validates multiples of 15 below 360); `normalise` moves every piece by whole cells so none is negative (the canvas grows to the top and left), endpoints hook onto a neighbour's end (`magnet`). `api.setWiredSegments(n)` is not undoable: the result goes to `useLibrary().reset` (history starts over). `StripStatus.connected` carries `segments` (wired) and `reported` (controller). Selecting a piece calls `api.identifySegment` after 150 ms (last wins). The wizard (`Wizard`, `onState`/`onDone`) shows its own state in the Strip header via `wizardLine`, asks `api.wizardState()` on mount (the Rust run outlives a tab switch) and offers Cancel on every step (Identify, Failed included; Identify times out after 2 min into Failed); the guide's dismissal is `localStorage` `deeboo.stripGuide` (try/catch), and it returns when help is switched on.
- Detection tab (`detection/DetectionTab.tsx`, `Timeline.tsx`, `ThresholdLine.tsx`, `ChangesSlider.tsx`, `history.ts`): history is a 32-beat ring (`pushBeat`) fed only by `detector` events; SVG lanes redraw per beat and not while the window is hidden. Each lane has a fixed right-hand column (`data-readouts`) holding the green dB labels, aligned to their line, so nothing sits over the waveform. The calm lines and labels show what the detector applies (stored value minus `sensitivity - 5`; the riser is not shifted) and drags save value plus that shift. Threshold lines drag (or arrows, 1 dB) within the Rust ranges and save via `setDetectionThresholds` (debounced); `ChangesSlider` maps 5 steps to sensitivity `[1,3,5,7,9]`; "Reset to defaults" is one `saveSettings`. Sensitivity and thresholds belong to the active audio input: the top-level settings fields are the active input's, and a `saveSettings` that changes `audioInput` returns that input's stored values (or the defaults), so always take the saved value back into state. Mock: `?mock&noclock` shows the no-clock state.
- Setup tab (`setup/SetupTab.tsx`): every control saves at once through `api.saveSettings` (no undo; the top bar says so). MIDI list: `api.listMidiSources` once plus the `midi-sources` event (`api.onMidiSources`), never polling. Light latency steps 10 ms within 0..=500 (typed values clamp). "Calibrate" calls `api.calibrateLatency(true)` (Rust `calibrate_latency`: engine flashes all wired segments white on each beat, free-running at 120 BPM when there is no clock, never persisted); the UI switches it off on tab leave, `beforeunload` and unmount, and Rust on editor close or when the strip disconnects or the lights go off. Setup shows «Connect the strip first.» or «Turn the lights on to calibrate.» instead of the button. Microphone access reads "allowed" only from a working stream; there is no reliable denied signal and no opener permission, so no System Settings link. Quit uses `api.quit` (`allow-quit` in the editor capability).
- Visual review without Tauri: `npm --prefix ui run dev`, open http://localhost:5173/editor.html?mock (in-memory api in `editor/mock.ts`, DEV only; `scripts/check-mock-treeshake.sh` in `just lint` fails if it reaches `ui/dist`).
- Popover visual review: http://localhost:5173/index.html?mock (`src/mock.ts`, DEV only; flags `&noclock`, `&nostrip`, `&striplost`, `&audiofail`); the same tree-shake check covers it. Status carries the palette in force (`selection.palette`, also under Auto: Rust `Selection::in_force`). Settings live in the editor's Setup tab; the popover has none. Status dots: Clock is red when `midi.ok` is false (chosen source missing), Audio is red when `audio.failed` (capture could not open or died; it reopens on the next play, Setup and Detection say "Capture failed"), and the Strip dot opens the Strip tab (its help texts say "Strip tab", never Setup).
- Tests are Vitest + jsdom with `api` mocked; see the `writing-tests` skill.
- Menu bar item (`src-tauri/src/tray.rs`, frames from `just tray-frames`): one item, the glyph never blinks. Lights on: green glyph (accent `#2dd4bf`, names `tray-<moment|stopped>[-forced]-on[-lost]`, not a template); lights off: black template glyph. Lost (no clock or strip): red dot, coloured (grey when the lights are off). Each frame is set with `set_icon_with_as_template` (a separate `set_icon` resets the template flag on macOS). The BPM title and the moment icon stay.
